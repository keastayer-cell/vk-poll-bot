# Эксплуатация

## Перенос справочника при включении новых функций

Актуальные 47 профилей из теста перенесены в `/opt/vk-poll-bot/players.json`
отдельно от рабочего `state.json`. Файл содержит только справочник игроков:
рейтинги, роли, ФИО и дополнительные имена; приглашённые также сохранены.
Права файла — `600`, владелец — `vkbot`; в Git он не включается.

Старая production-версия не поддерживает поле `players` и перезаписала бы
его при сохранении состояния, поэтому рабочий `state.json` не изменён.
При первом запуске новой версии приложение импортирует этот справочник
в `state.json["players"]`, сохраняя все остальные поля, затем переименовывает
файл в `players.json.imported`. Повторные запуски не заменяют актуальные оценки.
Режим `--check` импорт не выполняет. Тестовые опросы, команды и статистика
не переносятся. После включения правки выполняются через основной бот.

## Автодеплой через GitHub Actions

`.github/workflows/ci.yml` проверяет push в `main` и pull request: Ruff,
pytest, компиляцию Python и синтаксис скрипта выкладки.
`.github/workflows/deploy.yml` при push кода в `main` или ручном запуске
выполняет те же проверки, затем загружает релиз по SSH в
`/opt/vk-poll-bot-release` и запускает фиксированный серверный скрипт
`/usr/local/sbin/vk-bot-apply-release`.

Для работы нужны repository secrets `VPS_HOST`, `VPS_USER`, `DEPLOY_KEY`
и `SSH_KNOWN_HOSTS` (проверенный SSH host key сервера).
Выкладка разрешена только при repository variable `AUTO_DEPLOY_ENABLED=true`.
При `false` или отсутствующей переменной deploy job пропускается, включая
ручной запуск. Изначально настроено `false`; при согласованном запуске
новой версии установлено `true`, следующие push в `main` запускают выкладку.

Пока существует `/etc/systemd/system/vk-poll-bot.service.d/test-runtime.conf`,
выкладка основной версии блокируется до копирования кода и изменения зависимостей.
Переход с тестового запуска выполняется отдельно; workflow сам его не отключает.
Нельзя включать автоматическую выкладку до согласованного переноса рейтингов
из теста в основную версию.

При разрешённой выкладке обновляются только `src`, `main.py` и `requirements.txt`
в `/opt/vk-poll-bot`. `.env`, `state.json`, резервные копии и тестовый каталог
не копируются и не удаляются. Сервис перезапускается, затем проверяется, что
процесс стабилен 20 секунд и API/Long Poll доступны через `main.py --check`.
У VK-бота пока нет heartbeat-файла, как у Telegram-бота.
При ошибке workflow показывает журнал и завершается с ошибкой; автоматического
отката пока нет.

`/usr/local/sbin/vk-bot-apply-release --check` выполняет только
предварительную проверку без установки зависимостей, копирования файлов
или перезапуска сервиса. Саму выкладку выполняет запуск без `--check`.

SSH доступ настроен отдельному пользователю `vkdeploy`. Forced command
`/usr/local/bin/vk-bot-deploy-gateway` допускает только `probe`, `preflight`,
`upload` и `apply`; произвольные SSH-команды запрещены. Архив принимает только
обычные файлы Python приложения, `main.py` и `requirements.txt`, без ссылок,
секретов или выхода за каталог. Sudo разрешает только фиксированный root-owned
deploy-скрипт; зависимости устанавливаются от имени `vkbot`, а не root.
Изменения самих скриптов в `deploy/` требуют отдельной установки администратором
и автоматически с кодом бота не выкладываются.

## Проверка конфигурации и API

```bash
/opt/vk-poll-bot/.venv/bin/python /opt/vk-poll-bot/main.py --check
```

Успешный результат: `OK: VK API и Bots Long Poll доступны`.

## Запуск через systemd

```bash
sudo cp deploy/vk-poll-bot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now vk-poll-bot
sudo systemctl status vk-poll-bot
```

Логи:

```bash
sudo journalctl -u vk-poll-bot -f
tail -f /opt/vk-poll-bot/bot.log
```

## Безопасная проверка

1. Оставить `ENABLE_SCHEDULER=0`.
2. Запустить бота в тестовой беседе.
3. Проверить `/where`, `/poll`, кнопки, `+1`, `/status` и `/close`.
4. Только после проверки указать рабочий `VK_PEER_ID`.
5. Включить `ENABLE_SCHEDULER=1` и перезапустить сервис.

Файл `.env` и `state.json` должны иметь права `600` и не должны попадать в Git.

## Изолированная тестовая беседа на VPS

На VPS `139.100.237.243` основной код остаётся в `/opt/vk-poll-bot`.
Тестовый пакет находится в `/opt/vk-poll-bot-test`, состояние — в
`/opt/vk-poll-bot-test/data/state.json`. `deploy/test_runtime.py` подключает
старый основной пакет и новый тестовый пакет в один Long Poll процесс.
Тестовая беседа — `2000000001`, основная — `2000000002`.
В тестовой беседе нет расписания и личных уведомлений админам.

Первоначальный демонстрационный справочник содержит 16 вымышленных полевых
и 4 вратаря из `deploy/test-players.json`. Перед запуском основной версии
тестовый запуск отключён; каталог оставлен как архив. Описанные ниже команды
действовали только при подключённом test runtime:

```text
/demo 10    заменить тестовый опрос на 8 полевых и 2 вратаря
/demo 11    9 полевых + 2 вратаря, составы 5 + 4
/demo 12    10 полевых + 2 вратаря, составы 5 + 5
/demo 13    11 полевых + 2 вратаря, составы 6 + 5
/demo 14    12 полевых + 2 вратаря, составы 4 + 4 + 4
/demo 15    12 полевых + 3 вратаря; если в справочнике 2 вратаря — 13 полевых + 2
/demo 20    заменить тестовый опрос на всех 20 (распределение пока не поддерживается)
/teams      распределить полевых, показать вратарей отдельно
/status     показать записавшихся
/stats      реальные ДА в закрытых тестовых опросах, без приглашённых
```

`/demo` заменяет только тестовый состав, не рейтинг. Справочник и оценки
можно посмотреть любому пользователю через `/players` в тестовой беседе или
личке. При вызове в беседе список отправляется вызвавшему в личку;
в беседе остаётся подтверждение или ссылка на бота, если личка закрыта.
Антон может изменять их через `/rating`, `/position`, `/alias` и
`/players sync` в обоих местах. `/stats` доступна всем в тестовой беседе и Антону
в личке. Эти команды в личке направляются в тестовый пакет;
прежние команды, включая `/announce`, — в основной пакет.

Запуск подключён через `/etc/systemd/system/vk-poll-bot.service.d/test-runtime.conf`.
Для возврата к прежнему запуску удалить только этот drop-in, выполнить
`systemctl daemon-reload` и `systemctl restart vk-poll-bot`. Тестовый каталог
можно оставить: основной процесс его не использует.
